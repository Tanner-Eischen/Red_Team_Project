# HF-04/HF-05 offline discovery policy — November 1, 2026

The offline controller can harden all-pass discovery tasks, select a different operator from reviewed failure evidence, revalidate immutable children and retest the same lineage under matched harness/model profiles. This is implementation and offline-control evidence. Injected adapter outcomes are explicitly marked `offline_contract_test`; none are model-capability measurements. No provider request or authoring LLM was invoked.

## Configuration migration

Existing `schema_version: "1"` campaigns retain their historical failure-only revision semantics and scalar `budgets.max_task_revisions`. New behavior requires `schema_version: "2"` and an explicit `discovery_policy`. Schema 2 rejects a nonzero legacy revision scalar rather than silently choosing between competing limits. Fixed evaluation rejects any adaptive policy and never invokes the new controller.

The policy separately caps revisions per immutable lineage, total revisions, generation attempts, unchanged matched-outcome observations, per-tier attempts and exploratory promotions. Every task state/action includes the triggering trial IDs, policy version and reason. Transitions are checked against a finite permitted table, appended to `candidate-transitions.jsonl`, stored by content hash and attached to relevant immutable trial events. A failed control, timeout, missing evidence or provider/infrastructure error cannot drive a child.

`budgets.max_provider_retries_total` independently bounds extra provider retries. Its default `None` preserves legacy per-cell behavior. An explicit ceiling skips further retries while retaining provider errors and continuing remaining primary cells; it does not silently spend the retry allowance on extra primary work. Unknown usage still stops the campaign for reconciliation. A 12-cell pilot plus two retries needs both `max_model_attempts: 14` and a per-tier ceiling of at least 14. Both pilot profiles must be in the same tier to run the complete pilot matrix without adaptive tier selection.

Do not reuse historical campaign IDs or preregistration hashes after changing the configuration shape. Claim/restart protections remain intact. Create a new campaign/frozen registration explicitly; this is not an automatic resume or a cost-ledger reset.

[Zero-spend example](../configs/campaigns/offline-discovery-policy.example.yaml) has no models, zero dollars/tokens/attempts and zero retries. It only validates fresh generated f2 packages, after these are authored locally. Adding a model without independently changing those zero budgets cannot start an attempt.

## Immutable task and mutation contracts

New deterministic roots use `<family>-f2-<seed>` IDs and `family_version: "2"`. This prevents a regenerated seed from replacing a published legacy task version. Existing parent revisions retain their parent ID and increment the version once; children cannot overwrite an existing path. The 12 published packages remain unchanged and retain their original hashes.

New manifests bind requirement IDs and public behavior to verifier assertions, declared source/output transfer, public input hashes, private validation hash, oracle/quality protocol versions, difficulty parameters, parent/mutation IDs and synthetic source/licensing provenance. Independent expected values remain Decimal arithmetic, analytic raster-center sampling or integer-cell unions. Correct alternate implementations are accepted. Typed proposals allow a catalog ID, family, bounded level and mode; shell, dependency-installation and arbitrary code fields reject. No new hidden behavior is introduced.

All-pass selection follows the predeclared eligible operator order. Failure selection requires the latest appended confirmed review (SQLite row order, not wall-clock time or UUID ordering) of a finding on this exact immutable parent and a recorded `MODEL_FAIL`; stale/rejected/unreviewed or other-parent evidence cannot guide mutation. A finding's category chooses a relevant hypothesis, not a proven causal explanation. Children remain `difficulty_measured: false` until real matched experiments establish a difference.
